## Context

你给了一批小红书笔记链接，问能否批量下载到本地。我已实测：项目现有的 `pkg/scraper/xhs` 解析器换成移动端 UA 后，**32 条链接全部抓取成功（32/32）**，标题、正文、作者、标签、配图都能拿到，图片也能正常下载；而桌面端 UA 会被重定向到登录页。

但项目目前只有「小红书 → 奶茶圈发帖」，**没有任何本地归档代码**。本次要新增「小红书笔记批量下载到本地」能力，并直接用它把你给的 32 条笔记下载到 `articles/小红书/`。

已确认的两个偏好：
- Markdown 正文**去掉** `#话题[话题]#` 标记（标签仍写入 `metadata.json`）
- 视频笔记**只存封面图和 `video_url`**，不下载视频文件

## 归档格式

沿用豆包/ChatGPT 的归档约定：

```text
articles/小红书/2026-11/<标题>/
  <标题>.md          # # 标题 + 正文 + 本地图片引用
  metadata.json
  images/
    01-<8位hash>.jpg
    02-<8位hash>.png
```

`metadata.json` 字段：`external_id`（`xhs:<noteId>`）、`source`、`note_id`、`title`、`author`、`author_id`、`publish_time`、`url`、`markdown`、`images`、`failed_images`、`tags`、`video_url`、`synced_at`。现有管理页的 `scanArticles` 能直接识别这些字段。

## 实现步骤

### 1. 抓取器适配移动端页面
`pkg/scraper/xhs/xhs.go`
- 默认 UA 改为 iPhone Safari；显式配置了 `UserAgent` 时只用配置值。
- `Fetch` 在默认 UA 下解析失败时，自动用桌面 UA 重试一次；两次都失败才返回原来的「登录/风控」提示。
- 图片下载继续复用现有 `DownloadImage`（12MB 上限、Referer、Content-Type 校验）。
- 新增 `pkg/scraper/xhs/text.go`：把 `internal/xhssync` 里的 `#...[话题]#` 清洗逻辑抽成公开的 `xhs.StripTopicTags`；`xhssync.stripXHSHashtags` 改为调用它，现有奶茶圈行为不变。

### 2. 本地归档器（新包）
`internal/xhsarchive/saver.go` + `saver_test.go`
- `Fetcher` 接口：`Fetch` + `DownloadImage`，生产实现是 `*xhs.Client`。
- `Archiver.Save(ctx, rawURL)` 流程：
  1. 抓取笔记；无标题/正文/图片则报错。
  2. 按 `PublishedAt` 解析月份（失败用当前月），定位 `output_dir/小红书/YYYY-MM/`。
  3. 先按 `external_id` 查找已有目录；已完整则返回 `Duplicate=true`；图片数不足或缺 Markdown 则复用原目录补齐。
  4. 同名不同笔记自动加 `-2`、`-3`。
  5. 4 个并发 worker 下载图片到 `images/`，失败图片保留远程 URL 写入 Markdown。
  6. 生成 `<标题>.md`：标题 + `StripTopicTags(Desc)` + 本地图片引用。
  7. 写 `metadata.json`，`video_url` 只记录不下载视频。
- 复用豆包/ChatGPT 的 `sanitizeTitle`、`imageExt`、短 hash 命名模式；测试用 fake fetcher + 可替换 download 函数，不发真实网络请求。

### 3. 批量任务接入
`internal/server/xhs_batch.go`（新文件）、`internal/server/server.go`
- 复用现有 `BatchJob` / `batchManager` / `runBatchFunc` / `handleBatchZip`，照 `internal/server/chatgpt.go` 的既有模式。
- 新增路由：
  - `POST /api/xhs/batch`：接收 `{"urls":[...]}`，校验 `xhs.IsXHSURL`，支持从整段分享文本里提取链接，按笔记 ID 去重，上限 100 条。
  - `/api/xhs/status`、`/api/xhs/cancel`、`/api/xhs/zip` 直接复用通用批量处理器。
- `Server` 增加 `xhsArchiver` 字段和 `SetXHSArchiver` 注入点（接口类型，方便测试 fake）。
- 在 `runBatchFunc` 里把 `context.Background()` 换成随 `job.cancelCh` 取消的 context，取消能中断当前笔记的图片下载（对公众号批量同样有益）。
- 状态接口增加 `xhs_download_enabled`。

### 4. 独立初始化（不依赖奶茶圈）
`internal/app/app.go`
- 无条件创建 `xhs.NewClient()`（Cookie 沿用 `naicha_sync.xhs_cookie`）并注入 scraper + `xhsarchive.NewArchiver`。
- 保留现有 `xhsEnabled`（奶茶圈发帖）逻辑和页面注入逻辑不变；本地下载在 `naicha_sync.enabled: false` 时也能用。
- 不新增配置项；批量间隔沿用 `batch_delay_ms`。

### 5. 管理页 UI
`internal/server/admin.html`
- 新增卡片「批量下载小红书到本地」：多行链接输入、开始/取消、实时进度、完成后下载 ZIP；风格与现有「批量下载(多链接)」「豆包分享下载」一致。
- 运行状态里增加一行「小红书本地下载: 可用」。

### 6. 命令行
`cmd/xhs.go`（新文件）、`cmd/root.go`
- 新增子命令：`wx-mp-sync xhs --url <链接> --file <每行一个链接的文件> --output ./articles --delay 1200`
- 顺序下载，显示 `[n/总数] ✓ 标题 → 目录` / `✗ 失败原因`，结束打印汇总；支持 Ctrl+C 取消。
- 默认间隔取 `batch_delay_ms`。

### 7. 文档
`README.md`：新增「小红书笔记批量下载到本地」章节，说明管理页用法、CLI 用法、归档结构、去重规则、限流与 Cookie 可选配置；更新「归档结构」列表。
`config.example.yaml`：补充 `batch_delay_ms` 与 `xhs_cookie` 的说明注释（不新增配置块）。

### 8. 清理
删除探索阶段创建的临时目录 `tmpcheck/`（未跟踪文件）。

## 验证

1. `go test ./...`，新增归档器/批量接口测试通过。
2. `go build -o wx-mp-sync.exe .`
3. 用你给的 32 条链接实际跑一遍：
   `./wx-mp-sync.exe xhs --file <临时链接文件> --output ./articles`
   预期 **32/32 成功**，检查 `articles/小红书/` 下 32 个 `metadata.json`、Markdown 正文已去掉 `[话题]#`、每篇图片数与抓取结果一致。
4. 再跑一次同样命令，预期 **32 篇全部被跳过（Duplicate）**，验证去重。
5. 管理页冒烟测试：以 `--no-proxy --no-install-cert` 启动，打开 `http://127.0.0.1:9090`，粘贴几条链接走一遍批量下载与 ZIP 打包。

`articles/` 已在 `.gitignore` 中，下载结果不会污染仓库；奶茶圈发帖逻辑不改动。
